Cards Definition Guide app/data/cards

This document explains how to structure, organize and create card definitions for LodyLand. Cards are split across multiple YAML files and folders and then merged into a single cards.yml file for the game.

YAML based Multi-file fragments Automatic merge & validation

1. Folder Structure

All card fragments live under app/data/cards/. Files are grouped by theme (boosts, lands, packs, debug, etc.). 

app/data/cards/
├── boosts/
│   ├── resources.yml       # resource_boost cards
│   ├── xp.yml              # xp_boost cards
│   ├── cooldown.yml        # cooldown_boost cards
│   └── land_loot.yml       # land_loot_boost cards
│
├── lands/
│   ├── access.yml          # cards that unlock lands
│   ├── slots.yml           # extra land slots
│   └── specials.yml        # future special land cards
│
├── packs/
│   ├── starters.yml        # starter packs
│   └── events.yml          # limited-time event packs
│
├── debug/
│   └── test_cards.yml      # test cards (dev only, ignored in some flows)
│
├── normalize_cards_yaml.py # validator + merger
└── _README.md              # this file

The **merged** file used by the game is: 

app/data/cards.yml

Do not edit cards.yml by hand. It is generated automatically by normalize_cards_yaml.py from all fragment files under app/data/cards/.

2. How to Add a New Card

To create a new card:

  1. Pick the right fragment file (e.g. boosts/resources.yml for resource boosts).
  2. Make sure the file either contains a simple YAML list, or a cards: list.
  3. Add a new - key: ... block using the standard structure below.
  4. Run python app/data/cards/normalize_cards_yaml.py to validate and rebuild cards.yml.
Example

Inside boosts/resources.yml:

- key: wood_boost_2
  enabled: true
  card_type: resource_boost
  card_category: boost
  card_tags:
    - wood
    - forest
  card_label: Booster Bois II
  card_description: "+20% wood collected."
  card_image: /static/assets/img/cards/wood_boost_2.png
  card_rarity: uncommon
  card_gameplay:
    target_resource: wood
    boost:
      type: addition
      amount: 0.2
  shop:
    prices:
      - coins: 200
        diams: 0
        resources: {}
    show_in_main_shop: false
    show_in_village_shop: true
    buy_rules: null
  tradable: false
  giftable: true
  card_quantity: 0
  card_purchase_limit_quantity: null
  card_max_owned: 5

2.1 Standard Card Structure (Fragment)

Every card fragment must follow this structure:

- key: my_card_key
  enabled: true

  card_type: resource_boost           # land_access | resource_boost | cooldown_boost | xp_boost | land_slot | land_loot_boost | pack | ...
  card_category: boost                # high-level category for UI (land, boost, pack, ...)
  card_tags:                          # free tags for filtering/search
    - forest
    - wood
    - boost

  card_label: "Human readable name"
  card_description: "Human readable description"
  card_image: "/static/path/to/icon.png"
  card_rarity: common                 # basic | common | uncommon | rare | epic | legendary

  card_gameplay:                      # depends on card_type (see section 4)
    target_resource: wood
    boost:
      type: addition                  # addition | multiplier
      amount: 0.1

  shop:
    prices:
      - coins: 100
        diams: 0
        resources: {}
    show_in_main_shop: false
    show_in_village_shop: true
    buy_rules: null                   # reserved for future conditions

  tradable: false
  giftable: true

  card_quantity: 0                    # stock for special shops (0 = unlimited or not used yet)
  card_purchase_limit_quantity: null  # per-player purchase limit (null = no limit)
  card_max_owned: 5                   # max copies a single player can own

3. Card Types

Supported card_type values and their meaning:

card_type Description
resource_boost Increase amount collected for a specific resource.
cooldown_boost Reduce cooldown for a specific resource.
xp_boost Increase XP gains on collect actions.
land_access Unlock an entire land (forest, lake, beach, etc.).
land_slot Grant extra slots on a specific land.
land_loot_boost Increase loot across a land, optionally limited to a given tool.
pack Bundle of cards or items (starter packs, event rewards, etc.).
custom You may add new custom types if gameplay logic supports them.

4. Gameplay Examples

4.1 Resource Boost

card_type: resource_boost
card_gameplay:
  target_resource: wood
  boost:
    type: addition
    amount: 0.2          # +20% wood per collect

4.2 Cooldown Boost

card_type: cooldown_boost
card_gameplay:
  cooldown:
    resource_key: branch
    type: multiplier
    amount: 0.8          # cooldown * 0.8 = -20%

4.3 XP Boost

card_type: xp_boost
card_gameplay:
  xp:
    type: multiplier
    amount: 1.1          # +10% XP on all actions

4.4 Land Access

card_type: land_access
card_gameplay:
  target_land: beach     # unlocks the beach land

4.5 Land Slot

card_type: land_slot
card_gameplay:
  land: forest
  slots: 1               # +1 extra slot on Forest

4.6 Land Loot Boost

card_type: land_loot_boost
card_gameplay:
  target_land: forest
  target_tool: null      # or "hands", "rod", etc.
  loot:
    type: addition
    amount: 0.2          # +20% loot in Forest

5. Prices

A card can have one or several pricing options inside shop.prices. The player can buy using any one of the listed options. 

shop:
  prices:
    - coins: 100
      diams: 0
      resources: {}
    - coins: 0
      diams: 5
      resources:
        branch: 50

6. Shop Behaviour

Shop configuration controls where and how the card is offered to players.

shop:
  prices:
    - coins: 200
      diams: 0
      resources: {}
  show_in_main_shop: false
  show_in_village_shop: true
  buy_rules: null
  • show_in_main_shop: visible in the main in-game shop.
  • show_in_village_shop: visible in the village shop only.
  • buy_rules: reserved for future conditions (level, quests, time windows, ...).

Global economy-related fields live at the root level of the card: 

tradable: false                  # can be traded between players
giftable: true                   # can be gifted
card_quantity: 0                 # stock for some shops (0 = unlimited / not used)
card_purchase_limit_quantity: null  # max times a player can buy this card
card_max_owned: 1                # hard cap per player

7. Validation Rules

A card fragment is considered structurally valid if:

  • All required fields are present: key, enabled, card_type, card_category, card_tags, card_label, card_description, card_image, card_rarity, card_gameplay, shop, tradable, giftable, card_quantity, card_purchase_limit_quantity, card_max_owned.
  • shop.prices is a list, each entry having coins, diams and resources.
  • card_gameplay matches the semantics of card_type.

If any of these rules is broken, normalize_cards_yaml.py will stop, print a clear error message with the card key and file name, and will not regenerate cards.yml.

8. Image Checks

During normalization, each card_image is resolved on disk (under app/static/…) and checked:

  • If the image exists → OK.
  • If the image is missing → a warning is printed and the card is still accepted.

All missing images are also written to: 

app/data/cards/missing_card_images.txt

Each line contains: card_key, the original card_image value, the resolved filesystem path, and the source YAML file. This acts as a checklist for fixing broken assets.

9. Test Cards

Any file inside app/data/cards/debug/ is loaded but reserved for experiments and development. 

app/data/cards/debug/test_cards.yml

Use this file for temporary or debug cards that you do not want to ship in production builds. You can also exclude this folder when needed.

10. Normalization Script

The script normalize_cards_yaml.py is the single source of truth for merging and validating cards. 

# From the project root:
python app/data/cards/normalize_cards_yaml.py

What it does:

  • Recursively scans app/data/cards/ for .yml files.
  • Skips itself, cards.yml, backups, and optional debug files.
  • Loads cards from each fragment file:
    • either a plain YAML list - key: ...
    • or a dict with cards: [ ... ]
  • Validates each card strictly (see section 7).
  • Checks that card_image files exist on disk (section 8).
  • If any structural error is found → stops with a clear error and does not touch cards.yml.
  • If everything is valid → writes a fresh app/data/cards.yml grouped by card_type.

The game and the seeding logic (seed_cards_from_yaml()) only use app/data/cards.yml. Fragment files are your editing surface; the merged file is generated.
